## Question

Какая политика объёма и автоматического вытеснения применяется к собственной переписке между запусками, общий ли бюджет у всех чатов, какое значение используется по умолчанию и как применяется уменьшение лимита? Дополнительные параметры хранилища и будущее ручное удаление выделены в связанные билеты ниже.
## Context comment

2026-11-25. Пользователь сообщил о потере истории после перезапуска и явно попросил исправить её, затем отложил тестирование исправлений и попросил вернуться к MVP. В код добавлено локальное зашифрованное хранение последних 200 записей; этот лимит и конкретная схема хранения остаются параметрами прототипа, а не утверждённой политикой MVP. Позже пользователь попросил добавить удаление переписок в будущем; соответствующая запись внесена в документацию. Билет не закрыт: срок хранения, удаление и резервные копии ещё требуют решений.

## Session comment

2026-11-25. После явного откладывания фильтрации выбран первый доступный независимый билет по порядку и назначен codex до обсуждения. У него нет блокеров и нет зависимости от личных запросов или области скрытия. Обсуждается только срок хранения собственной переписки, без решения о том, как хранить скрытые сообщения и без реализации отложенного удаления.

Предложение (не принято): не удалять собственную переписку автоматически по возрасту. Альтернатива — установленный срок, например 30 дней. Ограничение 200 записей технического прототипа не считается автоматически выбранным лимитом MVP; объём хранилища уточняется отдельно. Проверки исправлений по-прежнему отложены.

## Decision comment — объём и кольцевая политика

2026-11-25. Пользователь выбрал пользовательский лимит объёма в настройках и кольцевую политику: после заполнения X[y] удаляются элементы с начала X[y[0]], затем следующие. Каноническое требование: REQ-025. Установленный агентом лимит 200 записей прототипа не является выбранным правилом MVP; автоматическая очистка по возрасту в днях не выбрана.

Политика — FIFO сохранённых записей: новая запись освобождает необходимое место вытеснением целых старых записей по порядку сохранения. Это не указание реализовать физически кольцевой файл. Формат хранилища и учёт служебных данных ещё не выбраны. Сохранение целостности записи требуется при любом варианте реализации.

Обсуждается собственная переписка по REQ-011, а не хранение чужих relay-пакетов до будущей встречи; последнее относится к отдельному билету маршрутизации и пока не решено. Текущий код с лимитом 200 записей не объявляется соответствующим новому правилу, изменения кода и отложенные проверки не выполнялись.

## Next question — общий бюджет или бюджеты чатов

Рекомендация (не принято): один общий бюджет для всей собственной переписки; при заполнении удаляются самые старые записи среди всех чатов. Альтернатива — отдельный бюджет для каждого чата. Нельзя без ответа подменять общий порядок FIFO удалением целого самого старого чата или отдельным лимитом сообщений каждого разговора.

После выбора области бюджета останутся параметры настроек и поведение при уменьшении лимита, нехватке свободного места или записи, которая сама превышает весь бюджет; они не считаются автоматически согласованными. Вопросы фильтрации спама остаются отложенными и для определения FIFO не требуются.

## Decision comment — единый бюджет

2026-11-25. Пользователь выбрал «общий»: один бюджет для всей собственной переписки; FIFO действует на последовательность записей всех чатов. Отдельные бюджеты разговоров не выбраны. REQ-025 и глоссарий уточнены. Удаляется необходимое число старых записей, а не автоматически целый чат. Прежняя запись об открытом выборе области бюджета теперь является историей до ответа.

## Next question — уменьшение бюджета

Рекомендация (не принято): если пользователь уменьшает лимит ниже фактически занятого объёма, показать объём необходимой очистки и попросить подтвердить применение нового лимита с удалением старейших записей по FIFO. При отмене сохранять прежний лимит и данные. Альтернатива — немедленно применять уменьшение и удалять данные без отдельного подтверждения. При обычном заполнении уже выбранного бюджета автоматическое вытеснение остаётся согласованным и не требует подтверждения каждого сообщения.

Границы настройки бюджета, его значение по умолчанию, учёт служебных данных и обработка нехватки места ещё не выбраны. Фильтрация спама остаётся отложенной; код и проверки не затрагивались.

## Decision comment — подтверждение уменьшения бюджета

2026-11-25. Пользователь ответил «ок»: уменьшение лимита ниже занятого объёма требует показа необходимого объёма очистки и подтверждения; после подтверждения применяется новый бюджет и FIFO-удаление, отмена сохраняет прежний лимит и историю. Обычное заполнение бюджета по-прежнему обрабатывается автоматически. Каноническое требование: REQ-026. Новое поведение не реализовывалось и не проверялось в прототипе.

## Next question — начальный бюджет

Предложение (не принято): начальный общий бюджет истории 100 МБ, изменяемый в настройках. Альтернатива — перед первым сохранением обязательно предложить пользователю выбрать объём, не назначая его автоматически. Это не выбирает минимальную/максимальную границу настройки, не гарантирует фактическое наличие свободного места и не задаёт хранение чужих relay-пакетов.
