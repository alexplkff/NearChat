# Проверенные ключи и Noise-каналы

2026-11-27. Новые текстовые конверты используют Noise IK (X25519/ChaChaPoly/SHA256) с Noise REKEY после каждого пакета и ограниченным хранением пропущенных ключей. Алгоритмы взяты из зафиксированной MIT-реализации swift-libp2p/swift-noise и проверяются вектором IK; NearChat отвечает за упаковку v3, хранение и жизненный цикл. Общий код сверки привязывает обе пары публичных ключей; ручное подтверждение сохраняется отдельно от согласия на переписку.

Интерактивное установление первого канала выбрано для текущей mesh-архитектуры с существующей идентичностью. Для адресата без готового канала текст ждёт в зашифрованной локальной очереди с исходным сроком, а отправка остальным продолжается. Асинхронное первичное установление по prekeys потребовало бы другой схемы распространения и удаления ключей. Ключи защищённого транспорта записываются до публикации ciphertext; подтверждение приёма задерживается до удаления использованного ключа. Сетевые служебные квитанции сохраняют отдельный подписанный формат метаданных и не определяют ключи текста. Этот адаптер, хранение состояний и модель угроз требуют самостоятельного аудита; прохождение векторов не является аудитом всей системы.
