Реализовано в существующем NearChat Lab; закрытые группы, согласие на личный диалог и окончательный протокол безопасности этим этапом не объявляются готовыми. [Техническое решение хранения](../adr/0001-bounded-sqlite-prototype.md).

## Записи и границы транзакций

`MeshStore` содержит два независимо ограниченных SQLite-архива. Их соединения и `MeshEngine` используются последовательно; в приложении — на главной очереди.

| Архив | Содержимое | Начальный бюджет |
| --- | --- | --- |
| Собственная переписка | Текст, порядок, исходящие конверты/задачи, результаты по адресатам, минимальные отметки дедупликации и ссылки на квитанции, известные ключи | 100 000 000 байт |
| Ретрансляция | Принятые чужие конверты, задачи, предложения передачи ответственности и их отметки; собственные и чужие конечные квитанции; уведомления об отказе | 5 000 000 байт |

Тела записей шифруются ChaChaPoly с раздельными ключами архивов, производными от секрета локальной идентичности. В AAD входят владелец, категория, вид и идентификатор записи. Метаданные SQLite — тип, ID, порядок, срок — не зашифрованы этим слоем. Это не полное шифрование файла SQLite. На iOS каталог и открываемые файлы получают `completeUntilFirstUserAuthentication`; каталог исключён из резервной копии. Keychain использует существующий `AfterFirstUnlockThisDeviceOnly`.

- Исходящая запись, конверты для зафиксированных адресатов и состояния доставки создаются одной транзакцией собственной истории.
- Принятый ретранслятором конверт и отметка предложения фиксируются одной транзакцией до `stored`. При отказе записи этой квитанции нет; возможен немедленный транзит.
- Собственный входящий текст и минимальная отметка дедупликации записываются вместе. Конечные квитанции отдельно принимаются в общий буфер ретрансляции при наличии места; их ciphertext не записывается в бюджет истории. При заполнении буфера возможна немедленная отправка без обещания отложенной доставки квитанции.
- При ошибке транзакции выполняется откат. Если сам откат завершается ошибкой, соединение перестаёт обслуживать дальнейшие операции. Повторное открытие после такого тяжёлого отказа пока требует перезапуска; обычный отказ записи повторно проверяется во время работы.

Старый `history-v1.sealed` читается до миграции. После успешной фиксации импорта и чтения нового архива приложение удаляет старый файл; при ошибке исходный файл сохраняется. Импорт имеет постоянную отметку выполнения и сохраняет локальный порядок. Старое неподтверждённое исходящее получает «Доставка не подтверждена»: очередь v1 восстановить невозможно.

## Квота и FIFO

VFS перед каждым увеличением файла считает обычные файлы своего каталога в блоках по 4 КиБ. Учитываются основной файл, живой rollback journal и старый файл истории при миграции; дочерний архив ретрансляции считается отдельно. Проверка и рост файла защищены mutex. В приложении работает один владелец каждого архива; конкурентное открытие независимыми владельцами не является поддерживаемым режимом.

`max_page_count` оставляет место под копии всех изменяемых страниц в журнале: `maxPages = (budget - 8192) / (2 × 4096 + 8)`. Поэтому в спокойном состоянии файл данных занимает примерно половину выделенного максимума; остальное требуется для транзакций. Бюджет включает накладные расходы и не обещает равный объём текста. Метаданные файловой системы, snapshots и RAM процесса не входят в эту метрику. Поведение SQLite при аппаратных отказах зависит от корректности файловой системы и синхронизации; абсолютной гарантии сохранения после любых сбоев нет.

При отказе из-за выделенного бюджета новая собственная запись повторяется с удалением старейших записей истории в той же транзакции. Вместе с каждой жертвой удаляются локальные исходящие задачи, ожидание передачи и результаты; уже переданные чужим устройствам копии не отзываются. Минимальная отметка входящего остаётся до срока, чтобы дубликат не вернул удалённый текст. Поздняя квитанция не создаёт историю заново. Заполнение архива служебными отметками может остановить приём даже после вытеснения текста: бесконечного дополнительного журнала нет.

Чужие принятые сообщения не вытесняются новыми. Сначала очищаются просроченные записи; если места всё равно нет, новая транзакция отклоняется. Ошибка нижележащей файловой системы не принимается за повод автоматически очистить собственную историю.

Начальные квоты передаются через `MeshStorageLimits`; малые значения используются только в тестах. По умолчанию — 100/5 МБ. В разделе «Настройки» доступны изменение двух лимитов, минимальные 5 МБ для ретрансляции, расчёт и подтверждение очистки. При успешном уменьшении буфера создаются уведомления предыдущим ответственным; восстановление с новым предложением работает для сохраняемого и RAM-отправителя. Настройки сохраняются в самих архивах. Подробности и границы атомарной замены: [Настройки квот](QUOTA-SETTINGS.md).

## Состояния передачи

| Событие | Результат |
| --- | --- |
| Сохранена собственная отправка | `queued`, «Ожидает маршрута» |
| Выполнена попытка передачи | `sent`, «Ожидает подтверждения», без галочки |
| Получено подписанное `stored` для актуального предложения | `handedOff`; отправитель сохраняет ожидание, показывает «Передано ретранслятору» |
| Следующий ретранслятор подтвердил хранение | Прежний удаляет полный чужой конверт, сохраняет ограниченную отметку передачи до срока |
| Конечный адресат принял сообщение, в том числе в явно обозначенную RAM | `applied` владельцу предложения и отдельная конечная квитанция автору; у автора ✓ |
| Входящее сообщение видно в активном приложении | Квитанция прочтения; у автора ✓✓ |
| Прошёл исходный срок без конечной квитанции | Локальная задача прекращается; «Доставка не подтверждена» |
| Пришла поздняя достоверная конечная квитанция | Существующая запись обновляется; прочтение не понижается до доставки |
| Пользователь выбрал «Повтор» | Новое сообщение, новый ID и срок; возможен повтор текста у адресата. «Отмена» закрывает предложение повторить |

Квитанция связывается с ID сообщения, адресатом и SHA-256 подписанного исходного конверта. Передача ответственности дополнительно связывается с UUID подписанного предложения. Восстановление после достоверного отказа меняет UUID предложения, сохраняя сообщение и срок: старое подтверждение не завершает новую попытку. `stored` не является конечной квитанцией; конечную квитанцию проверяют по ключу настоящего адресата. Бесконечной цепочки ACK квитанций нет: `control` — краткоживущий неперсистентный ответ.

У отправки нескольким текущим участникам отдельные ciphertext и задачи, но одна запись в ленте. Первая конечная квитанция даёт галочку; задачи остальных продолжаются. В Lab это рассылка доступным участникам, а не реализация закрытой группы. В payload общей рассылки входит идентификатор сеанса адресата: пакет для завершённого сеанса не принимается новым сеансом.

## Сроки, сеть и восстановление

Сообщение живёт до 24 часов от исходного создания. Каждый конверт содержит подписанный `expiresAt`; хранение, повтор передачи и перезапуск его не обновляют. Конечная квитанция получает собственные 24 часа от создания. Уведомление об отказе ограничено сроком исходного сообщения. Сохранённые задачи очищаются при доступном выполнении приложения; фон не гарантирован.

После холодного запуска история и задачи загружаются, сеть выключена. Передача возобновляется после «Начать». Таймер проверяет сохранение и истечение и при остановленной сети; это не отправка в сеть. Сохранённые задачи проверяются без требования близости `createdAt` к текущему времени. Для новых входящих пока остаётся ограничение прототипа: время создания не более чем на 5 секунд впереди часов получателя. Используется сохранённый срок по системным часам; монотонная оценка между перезагрузками и защита от скачков часов ещё не реализованы.

Максимум одного пути — 256 переходов. Конечный приём на последнем допустимом переходе разрешён; продолжение через промежуточный узел при остатке 1 запрещено. Сохраняемый ретранслятор уменьшает остаток один раз; автоматический повтор не уменьшает его заново. Немедленный транзит также уменьшает остаток, сохраняя предложение предыдущего ответственного. Подписанные предложения ограничивают значения, но не являются криптографическим доказательством всей цепочки против злонамеренного узла. Глобальное число копий остаётся отложенным вопросом.

Повторы — не чаще одного раза в 5 секунд на предложение, не более 16 задач за проход. Данные не отправляются в новый transport link до получения прямого объявления соседа. BLE и LAN используют один логический пакет; дубликаты подавляются независимо от канала. Доступный известный ключ позволяет поставить личное сообщение в очередь и при отсутствии текущего маршрута.

## Режим собственной переписки в памяти

Если запись недоступна, новые собственные входящие/исходящие сообщения принимаются в общий буфер до 5 000 000 учитываемых байт, пока есть место. Считаются сериализованные записи, конверты, состояния, временные квитанции и накладные расходы. Размеры неизменённых записей кешируются; это лимит содержимого, не всей памяти процесса. При заполнении новые сообщения приостанавливаются без вытеснения старых. Надёжная чужая ретрансляция в RAM не подтверждается.

Предупреждение видно во всех разделах, у несохранённых сообщений есть подпись. Сохранение повторяется автоматически; оставшиеся записи переносятся в исходном локальном порядке, с состояниями доставки и исходными сроками. Завершение процесса уничтожает оставшееся в RAM. Приложение повторяет открытие недоступного архива только с постоянной идентичностью; ошибка Keychain не даёт права переписать прежний архив временными ключами.

## Интерфейс и совместимость

История читается страницами по 200, доступно «Загрузить предыдущие». Это размер страницы, не лимит хранения. Время входящего — локальное получение; обновление состояния не переставляет строку. Нижняя навигация и скрытие клавиатуры сохранены.

Квитанция прочтения в приложении создаётся для входящей строки при видимости хотя бы 1% в ScrollView, открытом разделе сообщений и активном приложении. Это выбранный порог прототипа, не доказательство внимательного прочтения человеком; проверка реального поведения SwiftUI на устройстве ещё нужна.

Сетевой формат теперь v2, старый v1 отклоняется. Для обмена нужно обновить все участвующие устройства. Фреймирование BLE/TCP и локальные ключи не менялись. Локальный архив v1 имеет отдельный путь импорта.
