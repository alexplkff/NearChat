# Переписки и навигация

2026-11-26. Первый UX-срез после технического прототипа. Пользователь отдельно попросил открывать чат у последнего сообщения, чтобы не прокручивать историю вручную (REQ-108).

## Реализованное поведение

- Начальный экран — «Чаты». Общий чат закреплён первым; остальные диалоги и группы упорядочены по сохранённому порядку последних сообщений. Квитанции и прочтение не поднимают диалог в списке. Видны превью, время, непрочитанные, метки собеседников с одинаковыми именами и состояние архивной группы. Поиск работает по имени или метке, не по тексту всей истории.
- Нажатие открывает отдельную переписку с кнопкой возврата. Выбор получателя внутри переписки убран. Сведения о собеседнике, блокировка и управление группой доступны через «О чате».
- При каждом открытии показывается последнее сообщение выбранного чата. Загружается его собственная последняя страница до 200 записей, даже если этот диалог отсутствует в общей последней странице приложения. Более ранняя история загружается отдельно для этого чата.
- Пока пользователь находится внизу, новое сообщение и открытие клавиатуры сохраняют видимость конца переписки. При прокрутке к старым сообщениям автоматическое следование отключается, появляется кнопка «К последнему». Собственная отправка возвращает вниз. Догрузка старой страницы не является новым последним сообщением.
- Входящие и исходящие сообщения различаются расположением и фоном. В общем чате и группе у входящих видны имя и короткая метка отправителя. Подтверждённые доставка и прочтение по-прежнему обозначаются ✓ и ✓✓; ожидание и отсутствие подтверждения сохраняют свои состояния и действие «Повтор».
- Черновики разделены по чатам на время работы приложения. После перезапуска они не восстанавливаются. История сообщений сохраняется по прежним правилам.
- «Запросы и приглашения» открываются отдельно из списка чатов. Принятие личного запроса открывает диалог после успешного сохранения решения; при ошибке запрос остаётся на экране. Приглашения и отмена вступления используют прежний протокол.
- Нижнее меню содержит «Чаты», «Рядом» и «Настройки» и остаётся доступным с экранной клавиатурой. Профиль, способы связи и диагностика перенесены в настройки; достижимые участники и объявления закрытых групп находятся в «Рядом». Включение связи остаётся явным действием.
- Открытие списка не помечает сообщения прочитанными. Квитанции прочтения создаются только для видимых входящих в открытом чате активного приложения; на время перекрывающих экран окон прочтение приостановлено.

## История и совместимость

Добавлен производный индекс диалогов в памяти: идентификаторы, сохранённый порядок, признак непрочитанного и одно последнее сообщение на диалог. Он восстанавливается из зашифрованной истории при открытии; изменения учитываются после успешного COMMIT. Откат не создаёт фиктивные диалоги. FIFO, подтверждённая очистка и замена архива при изменении квоты обновляют индекс. Полный текст всей истории на каждый refresh не загружается. Индекс не меняет формат SQLite, ключи установки или сетевой протокол.

Это срез UX, а не закрытие всего билета интерфейса: удаление переписок, фильтрация спама и проверка собеседника по доверенному каналу остаются отдельными задачами.

## Фактические проверки

- `ConversationTests`: 7 сценариев — старый диалог вне общей страницы, собственная пагинация, непрочитанные и порядок после прочтения, удаление последнего сообщения, откат транзакции, RAM/восстановление, подтверждённая очистка и замена архива при изменении квоты.
- Полный набор ядра: 144 теста, 0 ошибок (`.build/ux-all-tests.log`).
- Сборки generic iOS без подписи и iOS Simulator успешны (`.build/ux-app.log`, `.build/ux-sim.log`).
- Ручная проверка в iPhone 17 Pro Simulator / iOS 26.3: диалог с 206 сообщениями открыт на последнем «Новая переписка • 205»; старый диалог вне общей страницы — на «История • 80». Проверены прокрутка назад и возврат кнопкой «К последнему», повторное открытие, одинаковые имена с разными метками, раздельные черновики, последнее сообщение над экранной клавиатурой, переход в настройки с клавиатурой, личный запрос и экран приглашений.

Для проверки использована отдельная Debug-копия `local.nearchat.uxqa` с аргументом `--ux-fixture`. Она создаёт искусственную историю во временном каталоге, не открывает Keychain основной установки и не запускает BLE/LAN. Дополнительные исторические записи импортируются как legacy без квитанций; реальные запросы и начальные сообщения формируются ядром между узлами внутри процесса. Поэтому эта UI-проверка не заменяет сетевые испытания на устройствах. Обычная сборка не включает тестовый сценарий автоматически; Release не содержит генератор.

На физический iPhone эта версия не устанавливалась. UI XCTest runner не использовался по прежнему выбору пользователя. Приход нового сообщения во время ручного чтения старой истории ещё требует проверки на двух устройствах; автоматическое следование ограничено соответствующим состоянием экрана.
